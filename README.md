# NIK Reader and Generator

A web tool for reading and generating NIK (Nomor Induk Kependudukan) numbers, live at [nik.zakiego.com](https://nik.zakiego.com). The NIK is decoded in the browser and never stored or sent.

## Features

- **Read NIK**: enter a 16-digit NIK to see its province, regency/city, district, gender, birth date and sequence number.
- **Generate NIK**: build a sample NIK from a region, gender and birth date, for testing and learning. It follows the official structure but isn't a registered number, and the last four digits can't be generated.

## Development

1. Clone the repository:

```bash
git clone https://github.com/zakiego/nik-reader.git
```

2. Install dependencies (Node 22, pnpm):

```bash
pnpm install
```

3. Run the development server:

```bash
pnpm dev
```

4. Open the URL from the startup log (usually `http://localhost:3000`).

Checks to run before opening a PR:

```bash
pnpm typecheck   # TypeScript
pnpm check       # Biome lint and format
pnpm test        # Vitest
pnpm build       # production build
```

`AGENTS.md` has the full guide for contributors and coding agents. `PRODUCT.md` describes who the tool is for, and `DESIGN.md` records the design system.

## Deployment

Deployed to Cloudflare Pages (custom domain [nik.zakiego.com](https://nik.zakiego.com)) via [`@cloudflare/next-on-pages`](https://github.com/cloudflare/next-on-pages). Every server route runs on the Workers runtime.

```bash
pnpm pages:build     # build the Pages worker
pnpm pages:preview   # run it locally on workerd
pnpm pages:deploy    # deploy
```

### Keeping requests off the Worker

The free Workers plan allows 100,000 requests a day, and Pages counts a request against it whenever the Worker runs. Two things keep this site well under that, and both are easy to undo by accident:

- **Reading a NIK and filling the region dropdowns happen in the browser.** The region datasets (~550 KB) load as a lazy `_next/static` chunk, which Cloudflare serves as a static asset. Importing `~/lib/region` directly from a component would put all of it in the initial bundle, so client code goes through `~/lib/region-client` or `~/utils/read` instead.
- **`_routes.json` lists only the paths that need server code.** It is generated by `scripts/build-routes.mjs` at the start of `pages:build`, from `pages/api` plus every redirect and rewrite `source` in `next.config.js`. Everything else (prerendered pages, `public/` files) is served straight from the CDN. Adding a redirect to `next.config.js` is enough; the script picks it up.
